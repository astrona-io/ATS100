# Overview: Install And Configure Harbor With harbor-helm (Playground)

This is a **playground**, not a lab. It starts a fresh cluster, installs Harbor with the `harbor-helm` chart, starts the workstation pod, and copies one image into Harbor. There is no task, no `astrona submit` and no pass or fail.

## What's in the box

- A single-node `kind` Kubernetes cluster. `kubectl` is already pointed at it.
- **Helm 3.22.1** on your machine, in `/usr/local/bin` or `~/.local/bin`, with the `harbor` chart repository added.
- **Harbor 2.15.4**, the Helm release `harbor` in the namespace `harbor`, chart 1.19.4, at `https://harbor.localtest.me:8443`. The administrator is `admin` with the lab-only password `Harbor12345`. The certificate was generated by the chart (`certSource: auto`).
- The project `inventory` with `inventory/podinfo:6.15.0`.
- The **workstation** pod in the namespace `workstation`, with `harbor`, `regctl`, `oras`, `cosign`, `curl` and `jq`, trusting Harbor's CA.

## Helpers

Paste these once in each new terminal. `ws` runs a command in the workstation. `token_realm` prints the realm the registry sends clients to.

```sh
ws() { kubectl -n workstation exec -i deploy/workstation -- "$@"; }
token_realm() {
  ws curl -sSI https://harbor.localtest.me:8443/v2/ | grep -i '^www-authenticate:'
}
```

## Practice tasks

- Run `helm -n harbor history harbor`, change one harmless value with `helm upgrade --reuse-values --set logLevel=debug`, and read the history again. Then roll back with `helm -n harbor rollback harbor`.
- Set `externalURL` to `https://harbor.localtest.me` (no port) and predict what `token_realm` prints before you run it. Put the right value back afterwards.
- Read the certificate on the wire with `openssl s_client` from the workstation, and find the SAN.
- Compare the CA from `/api/v2.0/systeminfo/getcert` with `ca.crt` in the Secret `harbor-nginx`.
- Write a `harbor.yml` for a machine called `harbor.inventory.example.com` with its own certificate files, and list which Helm values match each line.
